# Classroom Agent production installer

## Purpose

`Home Quran Learning Classroom Agent Setup.exe` is the Windows deployment
surface for academy laptops. A teacher double-clicks one executable, approves
the Windows elevation prompt, leaves the default Microsoft Teams platform
selected, and chooses Install. No PowerShell command or visible Agent console
is required after installation.

The build is generated by `scripts/Build-ClassroomAgentInstaller.ps1`. It must
be produced only on an Owner-controlled machine from an approved Git commit and
with the real VPS Agent API key entered through the hidden SecureString prompt.
The key is not printed. The generated EXE is credential-bearing and must be
transferred through an Owner-approved private channel and removed from general
Downloads/shared storage after installation.

## Installed behavior

- Windows 10/11 x64 build 19041 or later is required.
- Agent, TeamsHelper and the approved FFmpeg binary are self-contained in the
  single installer.
- The installer verifies trusted HTTPS health before changing the laptop.
- The current interactive Windows account receives limited scheduled tasks.
- The Agent and TeamsHelper start immediately and after every account logon.
- Tasks ignore duplicate starts, retry failures and have a bounded repeating
  recovery trigger.
- Microsoft Teams is the default platform. TeamsHelper is installed and
  started in this mode because it supplies the explicit Teams attendance
  evidence. Zoom/Other installs the core Agent without Teams UI automation.
- The core Agent records the screen, system audio and separately attributable
  teacher microphone track during authorized class windows.
- Live streaming is enabled. The Agent uses its durable `device.json` identity
  and publishes encrypted WHIP/WebRTC media only for an active authorized
  session.
- The cloud credential is removed from `appsettings.json` and stored with
  Windows DPAPI under `C:\ProgramData\AcademyAgent\Secrets`.
- Agent logs are written to
  `C:\ProgramData\AcademyAgent\Logs\ClassroomAgent.log` with bounded rotation.
- Repair/update is performed by running a newer approved setup EXE. The durable
  device identity and evidence directories are preserved.
- Windows Apps & Features can remove the binaries and startup tasks. Identity,
  recordings and evidence are deliberately preserved for audit safety.

## Live path

```text
Teacher laptop
  -> FFmpeg screen + system audio
  -> HTTPS WHIP signalling on VPS 443
  -> encrypted WebRTC media on ingress UDP 7885
  -> LiveKit room
  -> encrypted viewer media on TCP 7881 or UDP 51000-51100
  -> authenticated Owner/Admin/authorized Manager dashboard
```

The production deployment pins LiveKit server `v1.13.5` and Ingress `v1.5.0`.
LiveKit browser signalling is reverse-proxied at `/rtc`; WHIP signalling is
reverse-proxied at `/whip`. LiveKit tokens and Manager teacher scope remain
backend-enforced.

## Security boundary

The current VPS pilot authenticates Agent traffic with the existing Agent API
credential plus exact source-network allowlisting. The generated EXE therefore
contains a deploy-time credential inside its embedded payload even though the
installed copy is DPAPI-protected. It is suitable only for the Owner-controlled
academy fleet and must not be publicly distributed.

Per-device one-time enrollment and revocable device credentials remain the
required long-term replacement for the shared pilot credential. That work is
part of the separately governed Owner Device Management track and changes the
production authentication boundary.

## Production acceptance gates

The installer is not accepted merely because it builds. Before multi-laptop
rollout, one laptop must prove:

1. trusted HTTPS health with no certificate bypass;
2. one unique durable device identity and repeated heartbeat;
3. Agent and TeamsHelper tasks running in the teacher's interactive session;
4. headset teacher-microphone provenance;
5. one authorized Teams attendance flow;
6. one uploaded and playable recording;
7. one active-session live screen/audio view from the dashboard;
8. Agent restart recovery and Wi-Fi loss/recovery;
9. repair over the same version without identity duplication;
10. no secret in logs, UI, configuration JSON or command output.

Only after laptop 1 is green may the Owner approve laptops 2-5 one at a time.
